Grue is a game server that runs real text adventures and scores every turn, so language models can be compared on how well they explore, remember and obey a parser.

No. 01 — Why this exists

A benchmark that can’t be memorized

Zork is in the training data. Skerrin Light isn’t.

Agents are judged more and more on long, open-ended work: explore an unknown world, remember what you found, and act through an interface that punishes sloppiness. A text adventure packs all three into a few hundred turns, with a score that moves only when you do the right thing.

The classics have a catch. Walkthroughs for Zork are all over the web, so a high score may be recall instead of play. Grue ships original games that no model has seen, and marks the well-known ones so you can tell the difference.

01

Long-horizon exploration

No map is given. Rooms, keys and dead ends must be found, then revisited at the right moment.

02

Memory

The clue in turn 12 opens the door in turn 90. Context windows and scratchpads get tested for real.

03

Parser discipline

One short imperative command per turn. Extra prose, chained verbs and invented nouns all count against you.

11–15%Six budget models on Zork I. The memorized classic squeezes everyone together.
2–100%Nine models on Skerrin Light, an original. Here the spread is real.
No. 02 — How it works

A server, a client, one JSON protocol

Server

Grue

Runs real story files, parses every reply for location and score, ends games cleanly, and keeps a transcript and result for each session.

  • Z-machine
  • Glulx
  • native engine
  • REST
  • WebSocket
observation
text, score, location command
one line
Client

Brass Lantern

Turns each observation into a prompt, reads one command out of the model’s reply, and tracks cost, tokens and parse failures.

  • OpenRouter
  • OpenAI
  • Anthropic
  • Gemini
  • Ollama
Grue: run a server
git clone https://github.com/herzigma/grue && cd grue
npm install && npm run setup   # downloads the games
npm start                     # http://localhost:8081
Brass Lantern: play with a model
git clone https://github.com/herzigma/brass-lantern && cd brass-lantern
pip install -e . && cp .env.example .env   # then add a model key
brass-lantern play --game skerrin-light --model openrouter:openai/gpt-6.1-sol

Add your own game

Pull requests are welcome. Two paths:

1. Write a native game in JavaScript

A plain ES module: rooms, objects, puzzle hooks, scoring. The built-in engine supplies the parser, light and darkness, locks and undo. No compiler needed. Read the authoring guide.

games/original/mini.js
export default {
  title: 'Mini', author: 'You', maxScore: 1,
  start: 'cellar',
  rooms: {
    cellar: { name: 'Cellar', desc: 'A damp cellar. A key lies here.' },
  },
  objects: {
    key: { name: 'rusty key', syn: ['key'], loc: 'cellar',
      after: { take: (g) => { g.award('key', 1); g.win('Free!'); } } },
  },
};

2. Add a Z-machine or Glulx file

Pick a story file from the IF Archive, add an entry to games/games.json, and run npm run setup. Grue checks the sha256. See the README section.

games/games.json
{
  "id": "lost-pig",
  "title": "Lost Pig",
  "format": "zcode",
  "filename": "LostPig.z8",
  "url": "https://www.ifarchive.org/if-archive/games/zcode/LostPig.z8",
  "max_score": 7,
  "difficulty": "easy",
  "suggested_turn_limit": 300
}

Writing an original game is the most useful contribution. A game that can’t be in anyone’s training data is worth ten that can.

No. 06 — Play / API access

Browse freely. Playing needs a key.

Read

Public

Games, results and transcripts need no key. Everything on this page, and the same data over the API, is open to anyone.

Play

API key

Starting a session and sending commands needs a key, because each session runs an interpreter on this server. To get one, open an issue on GitHub.

Self-host

Free, no key

Run your own Grue in three commands (see How it works). Locally there are no keys to manage and no limits but your own machine.

curl
# public, no key
curl -s https://grue.party/api/games
curl -s https://grue.party/api/results

# playing: key required
curl -s -X POST https://grue.party/api/sessions \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"game":"lantern-lane","meta":{"model":"my-model"}}'

# $ID is the session_id in the first reply
curl -s -X POST https://grue.party/api/sessions/$ID/commands \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"command":"look"}'

curl -s -X DELETE https://grue.party/api/sessions/$ID \
  -H "Authorization: Bearer YOUR_KEY"
Brass Lantern .env
GRUE_URL=https://grue.party
GRUE_API_KEY=YOUR_KEY
OPENROUTER_API_KEY=...
